name: parse-audit
description: Audit a Dart/Python/TypeScript project with code-parser and produce a full architecture report — class sizes, method counts, potential god classes, dead code hints, and structural overview. Run on any project to understand its shape before editing.
argument-hint: [path]
allowed-tools: Bash(code-parser *), Bash(jq *), Bash(wc *), Bash(find *), Bash(ls *)
---

Produce a full structural audit of the project at `$ARGUMENTS` (default: current directory).

## Steps

### 1. Collect raw data

```bash
# Full index
code-parser ${ARGUMENTS:-.} --format json > /tmp/cp_audit.json

# File count by language
code-parser ${ARGUMENTS:-.} --format json | jq '
  group_by(.language) | map({language: .[0].language, files: length})
'

# Class count and method count totals
code-parser ${ARGUMENTS:-.} --format json | jq '
  {
    total_files: length,
    total_classes: [.[].classes | length] | add,
    total_methods: [.[].classes[].methods | length] | add
  }
'
```

### 2. Find structural issues

**God classes** (more than 15 methods):
```bash
jq '[.[].classes[] | select(.methods | length > 15) |
  {name, kind, method_count: (.methods | length), file: "?"}]' /tmp/cp_audit.json
```

**Empty classes** (0 methods — possible data-only or marker classes):
```bash
jq '[.[] | .file as $f | .classes[] |
  select(.methods | length == 0) | {name, kind, file: $f}]' /tmp/cp_audit.json
```

**Large files** (classes spanning more than 200 lines):
```bash
jq '[.[] | .file as $f | .classes[] |
  select((.line_end - .line_start) > 200) |
  {name, file: $f, lines: (.line_end - .line_start)}]' /tmp/cp_audit.json
```

**Deeply named methods** (hints at complex method like `_handleResponseAndUpdateStateWithRetry`):
```bash
jq '[.[].classes[].methods[] |
  select(.name | length > 35) | .name]' /tmp/cp_audit.json
```

### 3. Generate the report

Present the audit as a structured Markdown report:

```
# Project Audit — ./lib
Generated by code-parser

## Summary
| Metric | Count |
|---|---|
| Files indexed | 24 |
| Classes / interfaces / enums | 38 |
| Total methods | 187 |
| Languages | dart |

## Architecture Overview
List the top-level modules (subdirectories) and their class counts.

## Structural Warnings

### ⚠ God classes (>15 methods)
- `CheckoutController` — 23 methods  (lib/controllers/checkout_controller.dart:5–210)
- `ApiClient` — 19 methods  (lib/services/api_client.dart:3–189)

### ℹ Empty classes (0 methods)
- `AppException` [class]  (lib/models/exceptions.dart:3–6)  — likely data/marker class

### ℹ Large class bodies (>200 lines)
- `HomeScreen` — 287 lines  (lib/screens/home_screen.dart:8–295)

## All Classes
Group by file, list class names, kinds, and method counts in a table.
```

### 4. Suggest next steps

Based on the findings, recommend:
- Which classes to refactor first (god classes)
- Which files to investigate for the current task
- Whether the architecture looks healthy or fragmented
